1 · La idea en 60 segundos

Un plugin de Claude es una caja con cinco cosas dentro. Sólo una de ellas se puede llevar a otra plataforma:

Qué hay dentro¿Viaja?Por qué
skills/✅ SíEs el estándar abierto Agent Skills, que Perplexity y Mistral también entienden
commands/❌ NoLos comandos /algo son propios de Claude Code
agents/❌ NoNo existen los subagentes en el destino
Servidores MCP❌ NoEl destino no tendrá esas conexiones
hooks/❌ NoAutomatismos internos de Claude
Expectativa realista Esto no es un botón mágico de «convertir plugin». Extrae las skills, arregla lo que se puede arreglar solo, y te avisa por escrito de lo que no. Una skill que llamaba a una base de datos por MCP seguirá siendo un buen procedimiento escrito, pero no podrá consultar esa base de datos.

2 · Poner esta herramienta en tu ordenador

Sólo necesitas Python 3 (ya viene en macOS y Linux) y git. Comprueba que los tienes abriendo la Terminal y escribiendo:

python3 --version && git --version

Si ambos responden con un número de versión, ya está. Ahora descarga esta herramienta:

A Opción sin terminal

En la página del repositorio en GitHub, pulsa el botón verde Code → Download ZIP. Descomprime el archivo donde quieras, por ejemplo en tu carpeta de Descargas.

B Opción con terminal

cd ~/Descargas
git clone https://github.com/novanoticia/claude-skills-exporter.git
cd claude-skills-exporter

Esto sólo funciona una vez hayas publicado el repositorio (sección 6).

3 · Convertir un repositorio

Un solo comando. Abre la Terminal, sitúate en la carpeta de la herramienta y escribe:

python3 skills/plugin-to-agentskills/scripts/convert.py \
    https://github.com/USUARIO/REPO-CON-EL-PLUGIN \
    --out ./salida
Truco: no escribas la ruta a mano En macOS, escribe python3 (con el espacio final) y luego arrastra el fichero convert.py desde el Finder hasta la ventana de la Terminal. La ruta se escribe sola.

También funciona con una carpeta que ya tengas descargada:

python3 skills/plugin-to-agentskills/scripts/convert.py ~/Descargas/mi-plugin --out ./salida

Qué aparece en la carpeta salida/

Hay un solo archivo que importa por cada skill: su .zip Ese zip vale tal cual para Perplexity. Para Mistral lo único que hace falta es descomprimirlo. La carpeta que verás al lado del zip es exactamente eso: el zip ya descomprimido, para que no tengas ni que abrirlo.
Carpeta o ficheroPara qué sirve
mi-skill.zipEl archivo. Se sube a Perplexity sin tocarlo
mi-skill/Ese mismo zip descomprimido. Es lo que se sube a Mistral
INFORME-PORTABILIDAD.mdLéelo. Dice qué se rompió y qué se arregló
resumen.jsonLo mismo que el informe, para procesarlo con otro programa

Habrá un .zip y una carpeta por cada skill del repositorio original.

Lee el informe antes de subir nada Las skills marcadas con 🔴 contienen instrucciones que casi seguro fallarán fuera de Claude. Puedes subirlas igualmente —llevan un aviso incrustado para que el agente lo declare en vez de fingir— pero conviene saberlo de antemano.

4 · Subir a Perplexity Computer

1 Abre la página de skills

Ve a perplexity.ai/computer/skills.

2 Crea la skill

Arriba a la derecha: + Create skill → Upload a skill.

3 Arrastra el zip

Coge un fichero .zip de la carpeta salida/ y suéltalo en la ventana, sin descomprimirlo ni modificarlo. Repite para cada skill que quieras instalar.

4 Compruébalo

Abre un chat nuevo y pide algo que encaje con la descripción de la skill. Si no se activa, el problema casi siempre es la descripción — ver sección 8.

Un zip, una skill Perplexity espera encontrar la carpeta de una sola skill en la raíz del zip. Por eso la herramienta genera un zip por skill y nunca uno con todas dentro. Si comprimes varias juntas por tu cuenta, lo normal es que falle o sólo reconozca una.

5 · Subir a Mistral (Vibe Work)

Es el mismo material que acabas de subir a Perplexity, sólo que abierto: Mistral quiere la carpeta, no el zip.

1 Abre el panel de skills

chat.mistral.ai/work → pestaña Work → barra lateral izquierda → Context → Skills → New Skill.

2 Localiza la carpeta de la skill

En salida/, junto a cada .zip, hay una carpeta con el mismo nombre y sin la extensión: mi-skill.zip → mi-skill/. Esa carpeta es el zip ya descomprimido, con su SKILL.md dentro.

Si sólo conservaste el .zip, haz doble clic sobre él para descomprimirlo. Eso es todo: no hay ninguna conversión adicional.

3 Súbela

Entrega la carpeta con todo su contenido — SKILL.md y, si los hay, los ficheros de references/ y scripts/. Mistral mantiene las subcarpetas tal cual y acepta cualquier extensión, no sólo markdown: los .py y .yaml viajan igual.

El contenido de SKILL.md pasa a ser el panel Instrucciones de la skill.

4 Crear y probar

Create Skill, y lanza una tarea que encaje con la descripción. Si te sirve al resto del equipo, pulsa Publish.

A Mistral no le subas el .zip Y al revés: a Perplexity no le subas la carpeta. Es el mismo contenido, pero cada plataforma lo quiere en su envoltorio.

6 · Publicar en GitHub e instalar desde el marketplace

El destino es que puedas escribir en Claude Code /plugin marketplace add https://github.com/novanoticia/claude-skills-exporter y que funcione. Para eso el repositorio tiene que existir, ser público y llevar dentro la carpeta .claude-plugin/.

1 Crea el repositorio vacío

  1. Entra en github.com/new.
  2. Repository name: claude-skills-exporter — tiene que ser exactamente este, porque es el que aparece en la URL de instalación.
  3. Elige Public. Si lo pones privado, /plugin marketplace add no podrá descargarlo salvo que tengas git autenticado en esa máquina.
  4. No marques nada más — ni README, ni .gitignore, ni licencia. Si los marcas, el repo nace con ficheros y el siguiente paso se complica.
  5. Create repository.
El problema de las carpetas que empiezan por punto Todo el plugin depende de .claude-plugin/, y el Finder y el navegador ocultan las carpetas que empiezan por punto. Si la subes arrastrando sin darte cuenta de esto, el repositorio quedará incompleto y marketplace add no encontrará nada. Por eso la opción con Terminal es más fiable aquí: sube lo que hay, sin criterios de visibilidad.

2·0 Antes de nada: pon la carpeta en un sitio estable

La carpeta claude-skills-exporter que se generó vive en un directorio de trabajo temporal, con una ruta larga que cambia entre sesiones. Muévela primero a un sitio fijo: pulsa en la tarjeta de cualquiera de sus ficheros para abrirla en el Finder, sube un nivel hasta ver la carpeta entera, y arrástrala al Escritorio.

A partir de aquí las instrucciones asumen ~/Desktop/claude-skills-exporter.

2A Sube los ficheros · con Terminal (recomendado)

Pega esto de una vez en la Terminal:

cd ~/Desktop/claude-skills-exporter
git init
git add -A
git commit -m "Versión inicial"
git branch -M main
git remote add origin https://github.com/novanoticia/claude-skills-exporter.git
git push -u origin main

GitHub te pedirá autenticarte: usa el navegador si te lo ofrece, o un token personal como contraseña (tu contraseña normal de GitHub ya no sirve para git).

Si el push es rechazado Verás algo como Updates were rejected because the remote contains work that you do not have locally. Significa que al crear el repositorio marcaste alguna casilla (README, .gitignore o licencia) y por tanto no está vacío. Trae ese contenido antes de volver a empujar: 
git pull --rebase origin main
git push -u origin main
Si pull protesta con refusing to merge unrelated histories, añade esa opción: git pull --rebase --allow-unrelated-histories origin main.
No uses git push --force para salir del paso Funciona, pero borra del repositorio remoto lo que hubiera allí. En un repo recién creado con sólo un README auto-generado da igual; si el repositorio lleva tiempo y tiene historial, pierdes trabajo de forma irreversible. Coge la costumbre de hacer pull primero.

2B Sube los ficheros · arrastrando

En la pantalla que aparece tras crear el repo, pulsa el enlace uploading an existing file. Se abre una zona de arrastre.

Antes de arrastrar, en el Finder pulsa ⌘+⇧+. (comando, mayúsculas, punto) para que aparezcan las carpetas ocultas. Verás .claude-plugin en gris claro.

Selecciona el contenido de la carpeta claude-skills-exporter (no la carpeta en sí), .claude-plugin incluida, y arrástralo a la zona. Escribe un mensaje en Commit changes y pulsa Commit changes.

Si aun así .claude-plugin no sube, créala a mano con el paso 3.

Esta vía sirve igual con el repositorio ya creado y vacío: en lugar del enlace de la pantalla inicial, entra en el repositorio y usa Add file → Upload files.

3 Crear un fichero dentro de una carpeta oculta

En tu repositorio: Add file → Create new file. En la casilla del nombre escribe, incluyendo la barra:

.claude-plugin/plugin.json

GitHub crea la carpeta sola al detectar la barra. Pega el contenido del fichero y pulsa Commit changes. Repite con .claude-plugin/marketplace.json.

4 Comprueba que el repo tiene lo mínimo

Antes de instalar, mira la portada del repositorio en GitHub. Debes ver:

  • La carpeta .claude-plugin — con plugin.json y marketplace.json dentro. Si no aparece, la instalación fallará.
  • La carpeta skills.

GitHub sí muestra las carpetas que empiezan por punto; si no la ves, es que no se subió.

5 Instálalo desde el marketplace

En Claude Code, tres líneas:

/plugin marketplace add https://github.com/novanoticia/claude-skills-exporter
/plugin install claude-skills-exporter@pablo-skills-tools
/reload-plugins
LíneaQué hace
marketplace addRegistra tu repositorio como fuente de plugins. Se hace una sola vez
install …@pablo-skills-toolsInstala el plugin. Lo de después de la arroba es el nombre del marketplace (campo name de marketplace.json), no tu usuario de GitHub
reload-pluginsLo activa en la sesión actual sin reiniciar

Comprueba con /plugin: debe aparecer Claude Skills Exporter en la lista.

Desde la aplicación de escritorio es lo mismo por interfaz: Ajustes → Plugins → Añadir → marketplace, pegas la URL y Sincronizar.

Este plugin no fija versión, y es deliberado Sus manifiestos no llevan campo version. Claude Code usa entonces el hash del commit como identificador, de modo que cada git push cuenta automáticamente como versión nueva. Combinado con «Sincronizar automáticamente», no hay que hacer nada más al publicar un cambio.

7 · Actualizar el plugin después

Cada vez que cambies algo —una skill, el conversor, esta misma guía— publicar es un solo push. Este plugin está configurado para que sea así.

Por qué no hay que tocar ningún número de versión Los manifiestos de este plugin no llevan campo version. Cuando falta, Claude Code usa el hash del commit como identificador, así que cada git push es automáticamente una versión nueva. Es lo coherente con tener «Sincronizar automáticamente» activado en el marketplace.

1 Sube los cambios a GitHub

Con Terminal (el repositorio ya está enlazado, así que basta con):

cd ~/Desktop/claude-skills-exporter
git add -A
git commit -m "descripción corta del cambio"
git push

Sin Terminal, para un fichero suelto: ábrelo en GitHub, pulsa el lápiz, edita y Commit changes. Para varios ficheros, pulsa la tecla . estando en el repositorio: se abre el editor github.dev en el navegador, y desde ahí editas todo y haces Commit & Push de una vez.

Si la carpeta local ya no existe Clónala otra vez con git clone https://github.com/novanoticia/claude-skills-exporter.git, trabaja ahí y haz git push. No vuelvas a crear el repo ni a subir ficheros arrastrando sobre uno que ya tiene contenido: te arriesgas a duplicar o pisar cosas.

2 Refresca en Claude Code

Con «Sincronizar automáticamente» activado, no hace falta hacer nada: el cambio llega solo. Si lo tienes desactivado, o quieres forzarlo ya:

/plugin marketplace update pablo-skills-tools
/plugin update claude-skills-exporter
/reload-plugins
ComandoQué hace
marketplace updateBaja el catálogo actualizado de tu repositorio
plugin updateReinstala el plugin si el commit cambió
reload-pluginsLo activa en la sesión actual, sin reiniciar
El precio de no fijar versión Cada commit llega a quien tenga el plugin instalado, incluidos los que dejaste a medias. Irrelevante si eres el único usuario; molesto si lo comparte un equipo. Si llega ese momento, añade "version": "1.2.0" a plugin.json y a la entrada de marketplace.json, y a partir de ahí publica subiendo ese número — con la contrapartida de tener que acordarte de hacerlo en cada release.

8 · Aplicar un .patch o un cambio propuesto

Un .patch (o .diff) es un fichero de texto que describe qué líneas quitar y cuáles poner. Tiene esta pinta:

--- a/skills/mi-skill/SKILL.md
+++ b/skills/mi-skill/SKILL.md
@@ -3,7 +3,7 @@
-description: Esta skill genera informes.
+description: Cárgala cuando el usuario pida un informe mensual o un cierre.

Las líneas con - se van, las de + entran. El resto es contexto para localizar el sitio.

La web de GitHub no aplica ficheros .patch No hay ningún botón de «subir parche». Tienes tres caminos reales, de más fácil a más técnico.

A A mano, en el editor web · recomendado si el parche es pequeño

  1. Abre en GitHub el fichero que menciona la línea +++ b/….
  2. Pulsa el icono del lápiz (arriba a la derecha del contenido).
  3. Localiza las líneas - y bórralas; escribe en su lugar las + sin el signo de delante.
  4. Commit changes.

Para dos o tres líneas es lo más rápido y no te puedes equivocar mucho.

B Con el editor completo del navegador · varios ficheros

  1. Estando en tu repositorio en GitHub, pulsa la tecla . (el punto).
  2. Se abre github.dev, un Visual Studio Code dentro del navegador, con todos tus ficheros. Aquí sí se ven las carpetas ocultas.
  3. Edita lo que necesites en el árbol de la izquierda.
  4. Ve al icono de Source Control (las tres ramas), escribe un mensaje y pulsa Commit & Push.

C Con la terminal · el parche entero de una vez

cd ~/Descargas/claude-skills-exporter
git apply --check ~/Descargas/cambio.patch   # 1. ensayo: no toca nada
git apply ~/Descargas/cambio.patch           # 2. aplicar de verdad
git add -A
git commit -m "Aplicar parche"
git push

El primer comando es un ensayo en seco: si no dice nada, el parche encaja. Si protesta, el parche está hecho contra otra versión del fichero — no lo fuerces, vuelve a la opción A.

Ver un cambio de otra persona como parche

Si alguien te manda un pull request, puedes ver el parche crudo añadiendo .patch al final de su URL:

https://github.com/usuario/repo/pull/42.patch

Y para aceptarlo no hace falta nada de esto: en la página del pull request, botón verde Merge pull request → Confirm merge.

9 · Si algo falla

SíntomaCausa habitualQué hacer
No se encontró ningún SKILL.md El repo es un plugin de sólo comandos o sólo MCP No hay nada portable. Es el resultado correcto, no un error
Perplexity rechaza el zip El zip lleva varias skills dentro, o lo recomprimiste tú y quedó un nivel de carpeta de más Sube uno de los .zip que generó la herramienta, sin modificarlo
Mistral no acepta el archivo Le estás subiendo el .zip Descomprímelo y sube la carpeta que sale
Mistral dice «sube un archivo Markdown válido de skill» El markdown que le diste habla de una skill en vez de ser una skill: le falta el frontmatter Sube el SKILL.md que hay dentro de la carpeta, no un documento intermedio
La skill se instala pero nunca se activa La descripción dice qué hace en vez de cuándo usarla Reescríbela empezando por «Cárgala cuando el usuario…» y con las palabras que tú usarías al pedirlo
Se activa cuando no debe Descripción demasiado genérica Añade qué no cubre: «No la uses para X»
El agente dice que ejecutó algo que no existe La skill llamaba a una herramienta MCP Busca el aviso 🔴 en el informe y reescribe ese paso como instrucción neutral
git: command not found Falta git macOS: escribe git en la Terminal y acepta instalar las herramientas de desarrollo. Windows: git-scm.com
marketplace add falla o no encuentra nada Falta .claude-plugin/marketplace.json, o el repo es privado Mira la portada del repo en GitHub: ¿está la carpeta .claude-plugin? Si no, créala desde la web con la barra en el nombre (paso 6.3). Si el repo es privado, hazlo público
install dice que no existe el plugin Confundir el nombre del marketplace con el usuario de GitHub Después de la arroba va pablo-skills-tools, que es el campo name de marketplace.json. No es novanoticia
Instala pero los comandos no aparecen Falta recargar /reload-plugins, y comprueba con /plugin que está en la lista y activado
Subes cambios a GitHub y no llegan version sigue siendo la misma Sube el número en plugin.json y sigue la sección 7. Sin cambiar la versión, Claude Code sirve la copia cacheada
/plugin update dice «already at the latest version» No corriste marketplace update antes, o no subiste la versión Los dos comandos, en este orden: /plugin marketplace update pablo-skills-tools y luego /plugin update claude-skills-exporter
git push pide contraseña y la rechaza GitHub ya no acepta la contraseña de la cuenta para git Crea un token personal y úsalo como contraseña, o deja que se autentique por el navegador si te lo ofrece
Otro marketplace tuyo deja de funcionar Dos marketplaces con el mismo name Cada usuario sólo puede tener uno registrado por nombre: el segundo reemplaza al primero. Si vas a publicar más plugins, mételos todos en este mismo marketplace.json en vez de crear otro

La regla de oro de las descripciones

El 80% de los problemas de una skill importada están en una línea. El destino no lee el cuerpo para decidir si carga la skill: lee sólo la descripción, y la paga en tokens en cada sesión.

❌ Mal✅ Bien
«Esta skill genera informes financieros.» «Cárgala cuando el usuario pida un informe financiero, un cierre mensual o una comparativa presupuesto-real.»
«Ayuda con reuniones.» «Cárgala cuando el usuario pegue notas o una transcripción de reunión y pida un resumen o los acuerdos.»

Nota ética. Esta guía y la herramienta que documenta se han elaborado con asistencia de IA. Requieren revisión humana antes de usarse en producción, y las rutas de interfaz de Perplexity y Mistral pueden cambiar sin previo aviso: si no encuentras un botón donde dice aquí, consulta la documentación oficial de cada plataforma.
